PART 0

"내 컴에선 되는데"의 정체

로컬의 암묵적 전제 4가지 — 서버엔 없습니다.

  • 항상 켜진 내 PC
  • localhost 로 바로 접속
  • IDE가 알아서 빌드·실행
  • 내 PC에만 깔린 JDK·DB
배포란 이 4가지를 남의 컴퓨터(서버)에 다시 만들어주는 일.

PART 2 · 2-0

JAR이란

./gradlew build → build/libs/app.jar → java -jar app.jar

이 파일 하나가 너의 서버 전부. Tomcat이 안에 들어있습니다.

PART 2 · 2-1 (메인) · IaaS

AWS EC2에 손으로

EC2 = 클라우드에서 빌리는 빈 컴퓨터(IaaS) 한 대. 우분투만 깔린 백지 상태.

  • 받는 것: 공인 IP + 빈 우분투 + 접속 키(.pem)
  • 없는 것: Java · 내 앱 · 열린 포트 · 자동 재시작 — 전부 내가

🏠 비유 — IaaS(EC2)=빈 원룸 임대 · PaaS(Railway)=풀옵션 오피스텔 · SaaS=호텔. 다음 슬라이드에서 직접 7단계를.

여기서 일부러 고통을 느낀다. 빈 방을 받았으니 가구·가전(java·앱·방화벽·systemd)을 다 채워야 한다.
PART 2 · 🧪 시뮬레이터

EC2에 직접 올려보기 — 7단계

'다음 단계'를 한 번씩 누르며 명령·출력을 따라간다. 오른쪽 서버상태 ❌→✅, 외부 브라우저는 실행+포트 둘 다 돼야 200 OK. 누적 22분을 체감.
PART 2 · 2-2 · PaaS

Railway — git push면 끝

GitHub 저장소 연결 → 그 다음부턴 git push 한 번. 방금 손으로 한 7단계를 플랫폼이 대신.

PaaS=풀옵션 오피스텔. 빌드·컨테이너화·실행·도메인·HTTPS까지 자동. 취미·MVP엔 이게 정답.

방금 22분 걸린 7단계를 git push 한 번이 대신한다. 무엇을 대신해줬나? → 자동화 사다리로 이어짐.
PART 2 · 2-3 · 컨테이너 & 오케스트레이션

EKS — 왜/언제

먼저 컨테이너(Docker) — 앱+java+OS설정을 한 박스에 담아 어디서나 똑같이 실행.

컨테이너 1개는 손으로. 그런데 50개·100개면? 죽으면 살리고, 몰리면 늘리는 일을 오케스트레이션(쿠버네티스)이 자동으로.

Pod(실행 단위) · Deployment(원하는 개수 유지) · Service(고정 주소+LB). EKS=AWS 관리형 k8s. ⚓ 입문 팀엔 보통 과잉.

다음 슬라이드 시뮬레이터로 self-heal·스케일·롤링업데이트·Node 다운을 직접 보여준다.
PART 2 · 🧪 시뮬레이터

쿠버네티스 — 스스로 굴러가는 클러스터

요청 분배(LB)·Pod 죽이기(self-heal)·스케일·무중단 롤링 업데이트·Node 다운 재배치를 버튼으로 시연. "선언하면 알아서 유지"가 핵심.
PART 2 · 2-4 · GitOps

GitOps & ArgoCD — 종착

Git에 원하는 상태를 적으면 ArgoCD가 클러스터를 거기 맞춰 끊임없이 동기화(reconcile).

예) 누가 kubectl로 손대도 Git과 다르면 ArgoCD가 되돌림. 롤백 = git revert. 배포 이력 = git 이력. Railway가 아기 GitOps였죠.
