# 배포 교육 자료 기획안

- 날짜: 2026-06-04
- 참여: 사용자 + Claude
- 형식: 반나절(약 3h) · 개념 중심 이론 강의 · Spring Boot + Flutter 팀 대상

## 배경

팀에서 "배포 방법" 교육 요청. 팀원들은 로컬 개발/실행에는 익숙하나, Spring Boot 서버와
Flutter 앱을 실제로 "올려서" 서비스로 돌리는 과정을 막막해함. 핵심 진단: 지식의 양 문제가
아니라 **멘탈 모델(로컬 → 서버 → 외부 접속이 머릿속에 안 그려짐)** 문제. 따라서 "AWS 사용법
나열"이 아니라 "왜 이런 단계가 필요한가"를 그림으로 잡아주는 개념 강의로 설계.

## 핵심 결정사항

1. **형식**: 개념 중심(이론) 강의. 실습은 하지 않음(강사 데모/그림 위주).
2. **분량**: 반나절, 약 3시간 (상단). 2.5h 컷 레버 별도 마련.
3. **백엔드 배포 서사 — "자동화 사다리"**: 같은 JAR을 4단계로 올려봄.
   `AWS EC2(손으로 다 함) → Railway(git push면 끝) → EKS(컨테이너를 코드로) → GitOps/ArgoCD(Git이 진실)`
   - 난이도 사다리가 아니라 "플랫폼이 나 대신 얼마나 해주는가" 사다리로 프레이밍.
   - 콜백 장치: "Railway가 사실 아기 GitOps였다" → ArgoCD에서 회수.
4. **EKS 깊이**: 온으로 "왜/언제" + GitOps/ArgoCD 개념까지 (manifest 실습 X, 그림 위주).
5. **Flutter 깊이**: 내부테스트 ~ 스토어 배포까지 균등. 코드 서명·심사 흐름 포함.
6. **관통 장치**: "마스터 지도(요청 한 번의 여정)" 한 장을 매 부 회수하며 "지금 여기" 표시.
