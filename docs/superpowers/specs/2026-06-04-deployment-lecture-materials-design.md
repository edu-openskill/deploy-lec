# 배포 교육 자료 — 설계 스펙

- 날짜: 2026-06-04
- 상태: 설계 승인됨 (구현 플랜 대기)
- 선행 문서: `docs/discussions/2026-06-04-deployment-lecture-plan.md` (커리큘럼 기획안)

## 1. 목표

Spring Boot + Flutter 팀을 위한 **반나절(약 3h) 개념 중심 배포 교육 자료**를 제작한다.
산출물은 세 가지:

1. **강의 원고** (`deploy-lecture.md`) — 콘텐츠의 단일 진실의 원천
2. **인터랙티브 발표자료** (슬라이드 덱, 순수 바닐라 HTML/CSS/JS)
3. **시뮬레이터 2종** — 발표 중 직접 조작하는 인터랙티브 데모

핵심 교육 목표: 팀원의 "막막함"은 멘탈 모델 부재에서 옴 → **"마스터 지도(요청 한 번의 여정)"**
한 장을 매 부 회수하며 "지금 여기"를 표시해 전체 흐름을 머릿속에 그리게 한다.

## 2. 확정된 설계 결정

| # | 결정 | 비고 |
|---|---|---|
| D1 | 발표자료 = **슬라이드 덱** (←→ 넘김) | 스크롤리텔링/겸용 탈락. 라이브 발표에 최적 |
| D2 | 구현 = **순수 바닐라 커스텀 엔진** | 의존성 0, 시뮬레이터를 일급으로 임베드 |
| D3 | 비주얼 톤 = **키노트 라이트(B)** | 흰 배경, 굵은 산세리프, 인디고(#4f46e5) 포인트 |
| D4 | 시뮬레이터 = **요청의 여정 + 자동화 사다리** 2종 | 강의 두 기둥(1부·2부)과 대응 |
| D5 | md ↔ 슬라이드 = **수동 디자인** (자동변환 아님) | md 내레이션은 스피커노트로 재활용 |
| D6 | 완전 정적·오프라인 동작 | 나중에 GitHub Pages 호스팅 가능 |

## 3. 콘텐츠 — 6부 커리큘럼 (기획안에서 확정)

| 부 | 시간 | 제목 | 목표 |
|---|---|---|---|
| 0부 | 12' | 왜 배포가 막막한가 | "내 컴에선 되는데"의 정체 해부 |
| 1부 | 22' | 배포의 전체 그림 | 요청의 여정 + 핵심 개념 8개 |
| 2부 | 60' | 백엔드 올리기 — 자동화 사다리 | JAR→AWS→Railway→EKS→GitOps |
| 3부 | 20' | 도메인 + HTTPS | DNS·리버스프록시·TLS |
| 4부 | 40' | Flutter 앱 배포 | 빌드→내부테스트→스토어 |
| 5부 | 16' | 전체 잇기 + Q&A | 환경분리·비용·다음 한 걸음 |

- 관통 서사: **"플랫폼이 나 대신 얼마나 해주는가" 사다리** (AWS→Railway→EKS→GitOps)
- 콜백 장치: "Railway가 사실 아기 GitOps였다" → ArgoCD에서 회수
- 핵심 개념 8개(1부): 빌드산출물(JAR), 실행환경(JVM), 프로세스&포트, 공인IP vs 사설IP,
  방화벽/보안그룹, DNS, 리버스 프록시, TLS 인증서

## 4. 아키텍처 & 파일 구조

```
deploy-study/
├─ deploy-lecture.md          # 강의 원고 = 콘텐츠 단일 진실의 원천
├─ docs/
│  ├─ discussions/…           # 기획안
│  └─ superpowers/specs/…     # 본 스펙
└─ slides/
   ├─ index.html              # 덱 진입점 — 6부 모든 슬라이드 <section>
   ├─ css/deck.css            # 키노트 라이트 테마 + 슬라이드 레이아웃
   ├─ js/
   │  ├─ deck.js              # 슬라이드 엔진
   │  ├─ master-map.js        # 마스터 지도 컴포넌트
   │  ├─ sim-journey.js       # 시뮬레이터 1
   │  └─ sim-ladder.js        # 시뮬레이터 2
   └─ assets/                 # Pretendard 폰트 로컬 벤더링, 아이콘
```

**유닛 경계**: `deck.js`(내비게이션), `master-map.js`(지도 렌더링), 각 시뮬레이터 모듈은
서로 독립적으로 이해·수정·테스트 가능. 지도 노드 정의는 한 곳(공유 데이터)에서만 관리하고
`master-map.js`와 `sim-journey.js`가 함께 참조한다.

## 5. 슬라이드 엔진 (`deck.js`)

- **슬라이드 단위**: `<section class="slide" data-part="2-1">`, JS가 `.active` 클래스 토글
- **내비게이션**: `← →` / 스페이스 / 좌우 클릭존 / 진행바 / 현재 "n부" 인디케이터
- **해시 라우팅**: `index.html#part2-3` 딥링크 + 새로고침 시 위치 유지
- **스피커 노트**: `S` 키 토글 (md 내레이션 기반)
- **마스터 지도 연동**: `master-map.js`의 `renderMap(currentNode)` → 각 부 도입 슬라이드가
  "지금 여기" 노드만 하이라이트
- **프로젝터 대응**: 16:9 고정, `clamp()` 기반 반응형 스케일
- **접근성/가독성**: 빔프로젝터 환경 고려한 충분한 대비·폰트 크기

## 6. 시뮬레이터 설계

### 6.1 요청의 여정 (`sim-journey.js`, 1부 임베드)
- **상태 모델**: 노드 체인 `[Flutter앱 → DNS → 공인IP → 보안그룹 → Nginx → JAR:8080 → DB]`
  (마스터 지도와 동일한 노드 정의 재사용)
- **인터랙션**: 도메인 입력 → ▶ → 패킷 토큰이 노드를 순차 통과, 각 노드 점등 +
  하단 말풍선이 해당 단계를 한 줄로 설명 → 응답이 역방향으로 왕복
- **킬러 장치**: "보안그룹 443 열림" 토글 해제 시 패킷이 보안그룹에서 차단되는 연출
  (방화벽 개념 체득)

### 6.2 자동화 사다리 (`sim-ladder.js`, 2부 임베드)
- **상태 모델**: 4단계(AWS/Railway/EKS/GitOps) × 작업칩 목록. 각 칩이 단계별로
  "내가 함 🙋" / "플랫폼이 함 🤖" 중 어디 속하는지 정의
- **인터랙션**: 단계 클릭 → 칩이 🙋→🤖로 이동 애니메이션 → "위로 갈수록 내 손이 빈다" 시각화
- **콜백 연결**: GitOps 단계에서 "Railway 기억나죠?" 하이라이트

## 7. 시각자료(슬라이드 내 다이어그램) 목록

1. 마스터 지도 — 요청의 여정 (전 강의 재등장, master-map.js)
2. 자동화 사다리 비교도 (sim-ladder가 겸함)
3. GitOps reconcile 루프
4. Flutter 빌드→트랙→스토어 파이프라인
5. dev/prod 환경분리도 (앱 baseURL ↔ 백엔드)

## 8. 제작 순서 (구현 플랜의 뼈대)

1. `deploy-lecture.md` — 6부 원고 작성
2. 덱 엔진 골격 + 키노트 라이트 테마 + 마스터 지도 (샘플 2~3장으로 동작 검증)
3. 6부 슬라이드 전부 채우기
4. `sim-journey.js` (요청의 여정)
5. `sim-ladder.js` (자동화 사다리)
6. 반응형·프로젝터·전체 QA 폴리시

## 9. 범위 밖 (YAGNI)

- md → 슬라이드 자동 변환 빌드 파이프라인 (수동 디자인으로 충분)
- 실습 핸즈온 환경/계정 발급 가이드 (개념 강의이므로 제외)
- 슬라이드 프레임워크(Reveal.js 등) 도입
- 다국어 지원, 발표 녹화 기능

## 10. 완료 기준 (Definition of Done)

- 6부 전체 슬라이드가 `← →`로 끊김 없이 넘어간다
- 마스터 지도가 각 부 도입에서 "지금 위치"를 정확히 표시한다
- 두 시뮬레이터가 의도한 인터랙션(패킷 흐름/차단, 칩 이동)을 정확히 수행한다
- `deploy-lecture.md` 6부 내용과 슬라이드가 일관된다
- 인터넷 없이 `slides/index.html`만으로 동작한다
